# UI 设计说明

## 页面首先要回答什么

这个产品最重要的不是聊天框，而是“我为什么相信这次调查”。

所以第一版页面从上到下按这个顺序排：

1. 当前索引了哪个仓库；
2. 用户在调查什么；
3. 系统给出的结论；
4. 结论依赖哪些证据；
5. Agent 走了哪些步骤；
6. 检索方案当前的回归指标。

如果把证据和 Trace 藏到二级页面，RepoTrace 看起来会退化成一个普通 RAG Chat。

## 为什么是暗色界面

RepoTrace 的使用场景偏开发工具，而且证据卡片、Trace、错误码会比较密。暗色背景能减少大块白色区域带来的视觉噪音。

我没有做 IDE 式三栏布局，因为 V1 并不浏览完整源码。左侧只负责仓库上下文，主区域留给一次调查。

## 证据卡片

每条证据必须显示：

- 类型；
- 标题；
- 摘要；
- 分数；
- 重排原因；
- GitHub 原始链接。

`score` 不应该被包装成“92% 正确率”。它只是当前排序分数，所以 UI 只展示数值，不做百分比误导。

## 置信度

V1 的 `high / medium / low` 只是简单规则：

- 是否有候选证据；
- 是否使用 LLM；
- 回答里是否引用多条证据；
- Top1 排序分数是否达到最低阈值。

它不是经过校准的概率。

以后如果做真实数据集，需要把 confidence calibration 单独评估。

